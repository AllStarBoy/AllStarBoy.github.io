OSRS-inspired mobile MMORPG

Project Emberhelm Execution Plan

A practical build path for launching a mobile-first online RPG with one cross-platform client, a server-authoritative backend, and a focused MVP scope.

1) MVP Scope

  • Core loop: movement, combat, inventory, quests.
  • Single starting zone with a compact progression path.
  • No full-feature parity with OSRS at launch.

2) Engine Choice

  • Use Unity or Godot for Android + iOS from one codebase.
  • Finalize based on team familiarity and tooling needs.
  • Keep game logic structured for future platform expansion.

3) Online Architecture

  • Client + backend from day one.
  • Accounts, persistence, world state, inventory, and combat sync.
  • Chat service and reliable data storage included in MVP platform.

4) Mobile-First UX

  • Tap movement + optional virtual joystick.
  • Scalable HUD, readable text, touch-safe controls.
  • Battery/performance budgets tracked per milestone.

5) Vertical Slice

  • One zone, few enemy types, one quest chain.
  • Basic loot, equipment, and progression feedback.
  • Playable end-to-end loop before content expansion.

6) Networking & Anti-Cheat

  • Server-authoritative actions for combat and inventory.
  • Input validation and request rate limits.
  • Cheat telemetry for anomaly detection.

7) Device Optimization

  • Frequent tests on low/mid-range phones.
  • Optimize draw calls, memory, and asset size.
  • Measure network usage under real gameplay loads.

8) Content Expansion

  • Add skills, economy, social systems after core stability.
  • Expand world zones in iterations.
  • Keep release cadence tied to telemetry outcomes.

9) Live Ops Readiness

  • Patching pipeline and rollback strategy.
  • Telemetry dashboards, moderation, backup/recovery.
  • Support workflow for launch and post-launch events.

Current objective: deliver the vertical slice and validate performance/security baselines before adding large-scale content.
